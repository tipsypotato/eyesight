# 02 · 常见眼病教学模块

状态：待实施。范围为白内障、青光眼、斜视、弱视；医学来源编号见 [04](04-sources-and-i18n.md)。参数默认值和表现方式是产品设计决定，不能作为临床阈值或个体病程。

## 1. 共用疾病工作区（DIS-00）

### 1.1 用户路径

进入“常见眼病”，显示四张章节卡：名称、相关结构、一句学习目标、单眼/双眼/视觉发育标签及学习状态。白内障与青光眼沿用成人右眼；斜视使用双眼；弱视说明视觉发育机制。尚未交付的章节卡可列为“后续章节”，不可点击后进入空白页。

首次进入默认打开白内障的“正常结构”步骤。每章采用同一四步骨架：

1. **正常结构**：指认相关组织及正常功能，先建立比较基准。
2. **发生什么变化**：只打开该章节需要的参数或案例，不混入其他疾病变量。
3. **功能会怎样受影响**：并列展示机制与定性效果，说明模型表达和没有表达的内容。
4. **练习理解**：2—4 题，反馈后能返回相关结构或步骤，再继续原题。

无需先修课也能进入；遇到术语用“了解该结构”跳转临时资料层，关闭后回到原步骤，不切走整章。步骤可前后跳转；完成标准为访问四步并完成该章练习，查看答案记为练习完成但不记“答对”。

### 1.2 工作区布局与状态

桌面左侧章节/步骤，中央场景，右侧“本步问题 → 控制项 → 因果解释 → 来源”。窄屏沿用 [01 的底部面板](01-product-interactions.md)，步骤和下一步动作保持可达。当前病种、眼侧、正常/变化状态常驻；不能只靠材质变化暗示进入了病理场景。

第一次开章按本章默认值；以后恢复该章步骤、参数和已答题。章内第一步强制呈现正常基准，但保存已调整的病变参数；回到第二/三步恢复该参数。切到另一章前保存草稿、取消动画、还原模型，再应用新章。切换语言不改变以上任何内容。

“正常 / 变化”用于查看同一章节的两套说明性场景；它不会删除参数或已答记录。桌面可打开对照，镜头/目标/照明同步；移动端在同一视口切换。斜视对照始终显示一对眼，不能缩成四眼拼盘。“重置本章示意”恢复本章参数与场景默认值，不清空练习记录；青光眼等场景必须标注“重新演示，非临床恢复”。

课程可嵌入章节小测，调用同一个题目与答题引擎；不是复制另一套计分。可查看答案后回到机制场景，但返回题目时仍是已揭晓状态。任一章节的答案不得影响另一章节的场景或题目。

### 1.3 首期不提供的能力

不做照片诊断、症状打分、患者风险评估、治疗方案、用药/遮盖时长、手术操作训练或疗效预测。不要设计“滑到某个数值即患病”的任务。医学说明采用来源卡和当前内容审校状态，避免在每一步堆叠重复警示。

## 2. 白内障（DIS-CAT）

### 2.1 学习目标与场景

目标：能指出晶状体，解释晶状体混浊如何影响光的通过和视觉质量，并与角膜混浊、单纯失焦区分。依据 M02、M01。

沿用成人右眼。默认前段斜向剖面，角膜、虹膜保留邻近关系，晶状体高亮，睫状体/悬韧带可见。提供“晶状体局部 / 眼球内位置”切换：前者聚焦晶状体但保留边界参照，后者返回进入前相机；不能把晶状体漂在无参照黑背景中。

需要修改晶状体及核区的光散射/透明外观，保留当前非对称双凸形状。角膜、巩膜、瞳孔几何及虹膜纹理不随本章参数变化。瞳孔保持开口；透过开口看到晶状体变化，不把整个瞳孔填成白色实体。

### 2.2 控制项与默认值

| 字段 | 默认/范围 | 确定行为 |
| --- | --- | --- |
| `opacity` | 第二步默认 0.55，范围 [0,1] | 只控制混浊示意；0 清澈基准，1 本 demo 的最大显示强度；界面不用临床轻/中/重分期 |
| `view` | `context`；可选 `lens-detail` | 仅改变观察镜头，不改病变参数 |
| `preview` | `test-chart`；可切 `glare-scene` | 本地测试图用于对比对比度/雾感；点光源场景展示眩光示意 |
| `comparison` | 关闭 | 打开后固定正常 opacity=0，与当前参数使用同一镜头/测试图/光照 |

第一步始终 opacity=0，第二步启用保存的 opacity，第三步保留。这里不改变正常眼轴、晶状体薄透镜等效屈光力或外部镜片；几何光路计算仍在相同位置聚焦。现实白内障可伴随屈光变化，本章首期不模拟该部分，不能因此得出“白内障从不改变屈光”的结论。

### 2.3 逐步交互

| 步骤 | 用户动作 | 场景反馈 | 下一步条件 |
| --- | --- | --- | --- |
| 正常结构 | 点击晶状体或“定位晶状体” | 轮廓/标签与角膜、虹膜位置关系；正常透光说明 | 操作成功或显式跳过 |
| 发生变化 | 拖动混浊示意滑块 | 仅晶状体/核区混浊外观变化；旁边说明“光的透过与散射改变” | 可继续，不要求拖到特定值 |
| 功能影响 | 切换测试图与点光源，再看正常对照 | 定性雾感、对比度降低、眩光/光晕示意；清晰标注不是视力检查结果 | 访问后可进入练习 |
| 练习理解 | 回答结构与机制题 | 区分晶状体、角膜及视网膜，说明为何单纯调焦不等于消除混浊 | 完成 3 题，可带已看答案状态 |

光路示意可在晶状体处加少量标明“散射示意”的短虚线，不能把它伪装成经真实散射模型求出的光线；也不能由滤镜虚构一条新的焦距公式。光晕只是解释视觉质量，不是患者实际主观体验复现。

### 2.4 首期练习（题目 ID 固定，选项文字双语）

| ID | 题意与正确结论 | 典型误选反馈 |
| --- | --- | --- |
| `cat-location-01` | 白内障主要指哪一结构混浊？晶状体 | 角膜也可发生病变，但不是本章白内障所指结构；给出两者前后位置 |
| `cat-mechanism-02` | 相同焦点位置下，为什么画面仍可能有雾感/眩光？晶状体混浊改变透光与散射 | 不能把所有视物不清都归为焦点偏移 |
| `cat-distinction-03` | 普通外镜片是否等价于清除晶状体混浊？不是 | 镜片改变入射屈光关系，本示意中的混浊不会因此自动消失；不据此提供个体治疗判断 |

### 2.5 验收底线

在 opacity=0、0.55、1 切换和反复进入/离开章节后，角膜/巩膜/虹膜颜色、晶状体几何、眼轴和正常光学结果可还原；对照正常侧不被右侧参数污染。增大混浊不应自动改变眼压、视神经或瞳孔大小。若后续加入“更换混浊晶状体”的治疗原理展示，必须单独标成概念章节，不能用“恢复清澈”按钮暗示所有患者立即恢复完全正常视力。

## 3. 青光眼（DIS-GLA）

### 3.1 学习目标与必要新增结构

目标：理解青光眼涉及视神经损害；房水流出与眼压是重要机制/风险关系，但眼压高不必然已患青光眼，眼压正常也可能发生青光眼。早期可能没有明显视觉症状；已造成的损害不能靠本 demo 的“排水恢复”逆转。疾病关系依据 M03、M04；房水路线补充来源 M11 的访问范围见 04。

需要在前段补充 `iridocorneal-angle`（虹膜角膜角/房角，区域）和 `trabecular-meshwork`（小梁网，组织）两个教学目标。它们进入解剖注册表和中英文搜索，分别提供种类、位置、来源及材料说明；不把房角画成独立厚组织。小梁网采用环形滤过区示意，不声称表达所有微观细节。

两种观察位：“房水流出”和“眼底/视神经”。用双定位按钮顺序观察，不试图把前段和眼底在一个小视口同时放大。可缩略显示另一观察位作为导航，不重复第二个完整渲染器。

### 3.2 情景而非病程滑块

首期不提供 mmHg、杯盘比阈值、诊断分数或“压力→损害百分比”连续滑块。采用下面四个独立案例；不是从正常到末期的线性阶段。

| `scenario` | 房水通道示意 | 视盘/视神经示意 | 功能面板与关键说明 |
| --- | --- | --- | --- |
| `normal` | 小梁网路线正常流出 | 正常结构基准 | 正常参考；不作为患者正常眼底判据 |
| `outflow-risk` | 流出变慢，用箭头密度/停留提示 | 保持基准，不立即损伤 | “流出受限可使眼压升高；风险不等于已经发生损害” |
| `established-damage` | 本案例采用流出受限背景 | 单独创作的神经纤维/视盘结构变化示意 | 展示“可能的视野缺损示意”；不从通道动画实时计算损伤 |
| `normal-tension` | 不显示眼压升高；路线保持参考 | 使用另一独立的损害示意 | “正常范围的眼压也不能单独排除青光眼” |

默认第二步案例为 `outflow-risk`；第一步强制 normal。选择另一个案例保留镜头观察位，先取消上个案例动画，再将 outflowRelieved 设为 false 并应用新案例。`established-damage` 和 `normal-tension` 的“早期无明显自觉变化 / 可能出现缺损”是说明页签，不是拖动病程时间轴。二者都保留“早期可能无明显症状”的文字。

### 3.3 房水路线

以缓慢粒子/箭头表示：睫状突产生房水 → 后房 → 经瞳孔 → 前房 → 房角小梁网流出区。图例明确“仅展示小梁网流出路线；还有其他流出途径”。粒子是房水，不是光子或血液；使用与光路不同的颜色、箭头和文字。不要让玻璃体腔参与此循环。

`outflow-risk` 中只修改流出区标识和粒子停留，不把整个眼球吹成气球，也不通过动画帧数求出眼压。暂停/减少动态效果时保留完整静态箭头。选择“解除本例流出受限（概念演示）”后路线恢复，风险说明更新；若案例包含既有损害，损害和视野示意保持，出现“流出改善不等于已损伤部分再生”的说明。

### 3.4 视神经与视野

视盘/视神经变化用局部高亮、神经纤维分布简化或形态对比表达，必须标注“结构示意，不能据此诊断”。不要机械地按眼压线性缩小视神经、夸大眼球体积，或用某个杯盘比判定患病。

功能面板使用“视野范围示意图”，与外界测试图预览区分：同一注视点周围可见区域出现一个标注的局部/周边缺损示例，旁边说明实际缺损形态及主观感受不相同。首期不使用整圈黑边从外向内闭合，也不以透明滤镜表示所有青光眼患者眼前看到黑块。结构图与视野图是同一教学案例的两项说明，不能声称本模型可互相定量预测。

### 3.5 逐步流程与练习

1. 正常步骤定位前房/后房，查看房水路线，再切到视盘/视神经。
2. 变化步骤先显示 outflow-risk，用户暂停流动、点出流出区；再选择另外两种案例比较。
3. 功能步骤比较早期可能无症状与缺损示意，尝试“改善流出”并观察既有损害不消失。
4. 练习 4 题：

| ID | 正确结论 | 必须纠正的误区 |
| --- | --- | --- |
| `gla-route-01` | 后房→瞳孔→前房→小梁网路线 | 后房不是玻璃体腔；房水不沿视神经流出 |
| `gla-pressure-02` | 眼压升高是重要风险关系，不单独等于诊断 | 高眼压≠已经有青光眼损害 |
| `gla-normal-tension-03` | 正常眼压不能单独排除青光眼 | 不能由“正常压力”推断无病 |
| `gla-irreversible-04` | 控制风险/降低眼压不能让既有视功能损害自动恢复 | “重新演示”是软件重置，不是治疗结果 |

### 3.6 验收底线

切换四情景后保存/恢复正确；改善流出不恢复既有损害；正常眼压案例可单独呈现损害；在不显示视野缺损时仍保留早期无明显症状说明。显示箭头的起止点与实际前/后房、瞳孔、小梁网位置一致。闭角机制如后续实施，应作为独立情景解释房角阻塞，不能把本章流出受限一律称作闭角。

## 4. 斜视（DIS-STR）

### 4.1 为什么需要双眼

目标：看到双眼相对同一注视目标的眼位，区分正常会聚、内斜和外斜，理解斜视不等同弱视，也不等同所有眼外肌“无力”。依据 M06、M05。

单眼模型无法表达双眼是否同时对准同一目标，必须新增左眼实例及共同注视目标。首期只做双眼球、轴线和注视标记，不做完整头部、六条肌肉解剖、神经支配或个体斜视诊断。

### 4.2 坐标与选取约定

双眼场景以患者坐标为准：世界 +X 为患者左侧，+Y 向上，+Z 向前。成人右眼局部 +X 为鼻侧；左眼鼻侧朝 -X。OD 中心为 (-1.35,0,0)，OS 为 (1.35,0,0)，共同目标初始 (0,0,8)，均为教学归一化坐标，不能标为毫米。每只眼的光轴基准先朝向同一个目标。

右眼作为默认偏斜眼。左右眼都有独立 `EyeRef={side:'right'|'left', structureId}`；点击、标签和高亮必须包含眼侧，不能因共用材质或 ID 而同时选中两眼。左眼黄斑/中央凹与视盘的鼻颞关系需按左眼构建；不能只复制右眼再挪到左边，也不能简单负缩放后忽略法线、三角绕序与命中。

### 4.3 控制项

| 字段 | 默认/范围 | 行为 |
| --- | --- | --- |
| `alignment` | `normal`；可选 `esotropia`、`exotropia`、`custom` | 正常偏差 0°，内斜示意 +10°，外斜示意 -10°；均相对该眼正常注视方向 |
| `deviationDeg` | 0；范围 [-20,20] | 只控制偏斜眼的水平额外旋转；正值向鼻侧、负值向颞侧；用户拖动后 alignment=custom |
| `affectedEye` | `right`，可切 `left` | 改变偏斜眼，保留偏差语义符号和幅度；另一眼保持对准目标 |
| `targetDistance` | `far`；可选 `near` | 目标 z=8 / z=4；先分别重算两眼正常注视方向，再附加偏差 |
| `visualExplanation` | `alignment-only` | 可切 `adult-diplopia`、`child-suppression`，是不同教学情境，不是患者年龄滑块 |

数值只用于几何示意，不显示棱镜度、不分临床严重度，也不以此计算治疗量。左眼“向鼻侧”的世界旋转方向与右眼相反；内部可实现为 side-aware yaw，但对用户始终保留统一鼻/颞语义。

“显示视轴”可以切换；严格图注采用“简化注视方向线”，不声称真实视轴、光轴与瞳孔中心完全重合。正常近目标下两眼会聚是正常协调，不能因为眼轴不平行就标为内斜。

### 4.4 四步交互

1. **正常结构**：两眼均朝共同目标；切换近/远，看到正常会聚差异。提示“判断是否共同对准目标，不是判断两条轴线是否永远平行”。
2. **发生变化**：选内斜/外斜，只有偏斜眼额外转动；两条注视线与共同目标、未对准标记同时可见。调整偏差并切换眼侧，鼻/颞标记跟随眼侧。
3. **功能影响**：alignment-only 保持几何解释；adult-diplopia 用两组分离标记解释可能复视；child-suppression 用简化输入通路说明可能抑制一眼信息，并可能与弱视相关。不在真实场景上强制叠双影，也不暗示所有斜视都复视或所有儿童必然抑制。
4. **练习理解**：3 题，允许返回双眼位置对照。进入弱视的推荐入口是“了解视觉发育影响”，不能自动跳转导致未完成练习丢失。

| ID | 正确结论 | 误选反馈重点 |
| --- | --- | --- |
| `str-alignment-01` | 内/外斜按偏斜眼相对正常注视方向向鼻/颞侧区分 | 屏幕左右会随镜头/眼侧改变，不是定义 |
| `str-convergence-02` | 正常看近时会聚不等于斜视 | 两眼仍共同指向目标，与一个眼偏离目标不同 |
| `str-amblyopia-03` | 斜视是眼位不一致，弱视是视觉发育相关的视功能问题；可相关但不等同 | 外观整齐不能单独排除弱视，斜视也不保证一定弱视 |

### 4.5 验收底线

近/远目标时 normal 两眼均命中同一目标；内斜示意对两侧眼都向各自鼻侧；切换眼侧不改变实际偏差幅度；局部结构、眼侧标签、镜头和材质分别可恢复。不能把斜视唯一解释为“某条肌肉松弛”，也不将复视模拟作为必然症状。

## 5. 弱视（DIS-AMB）

### 5.1 学习目标与模型范围

目标：理解弱视与儿童期视觉发育中异常视觉输入有关，可能伴随斜视，也可能双眼外观和眼位都正常；改善光学输入不意味着已形成的发育问题立刻消失。弱视常影响一眼，也可能影响双眼。依据 M05、M06、M02。

基线为成人右眼。本章使用“眼部输入 + 简化视觉处理”机制图，标题明确“儿童视觉发育机制示意；眼部几何沿用成人教学模型”。不能把当前网格无说明地改名“儿童眼球”，也不能为省事把弱视画成晶状体混浊、视神经断裂或单纯光学离焦。

### 5.2 场景和案例

左/中央区域沿用 D 阶段的双眼输入，右/下区域增加两条输入通路汇入简化“视觉处理”框；神经信息用脉冲/图标，与光线样式不同。处理框只讲输入与视觉发育关系，不绘制虚构的脑区强度百分比。

| `causeCase` | 眼部输入示意 | 必须表达的区别 |
| --- | --- | --- |
| `anisometropia`（默认） | 双眼对准；右眼复用轴性近视光学基准，左眼用正常基准，输入清晰程度不同 | 外观无明显偏斜也可能出现弱视；不是“斜视的另一种叫法” |
| `strabismic` | 双眼均用正常屈光基准，右眼相对正常注视额外内偏 +10°，存在双眼信息不一致及可能抑制 | 斜视可能影响发育，但不是每个斜视者都弱视 |
| `deprivation` | 双眼对准且用正常屈光基准，右眼复用 opacity=0.55 的混浊示意，左眼清澈 | 原因可为介质混浊，弱视描述的发育结果与混浊本身不同 |

默认示例为单侧，不代表弱视必定单眼。三案例切换各自保留机制卡位置与改善输入开关；首次访问均为机制卡 0、开关关闭。切换到不同原因时使用对应示例参数，不沿用上一案例的内斜角或白内障混浊。原因案例的参数只为说明，不提供实际儿童的年龄、持续天数、视力表或严重度映射。

### 5.3 三段机制，不是治疗时间轴

变化步骤内有三个可直接点击的卡片：

1. **原因**：选择案例并定位输入问题，画清晰的原因标签。
2. **发育期输入异常**：突出两眼输入质量/一致性的差别，说明视觉系统发育受到影响。
3. **已形成的视觉功能问题**：眼部输入和视觉处理结果分开显示，指出“改变输入”与“发育结果”不是一个开关。

这些卡片不是按年份播放的病程动画，不给出统一关键年龄或某岁后绝不改善的阈值。可用静态箭头或短动画表达因果，不能把“弱视进度”滑块当时间、脑发育百分比或确诊工具。

### 5.4 功能步骤与交互

在 anisometropia 案例提供“改善光学输入（原理示意）”开关：打开后用现有矫正基准让右眼输入图变清晰；处理框仍保留“已形成的发育问题需专业评估，不能由此演示即时恢复”。在 strabismic 案例用“眼位回正的几何示意”，将额外偏差设为 0，只改变眼位和输入一致性；在 deprivation 案例用“解除输入遮挡的概念示意”，将示意混浊设为 0，只改变输入，不自动清除发育结果。关闭开关回到本例输入基准，不修改其他案例或外部疾病章节。

这些开关不是治疗按钮。视功能结果用文字与输入/处理关系图表达，可配定性分辨任务示意，不能声称用一个模糊滤镜重现所有弱视者看到的世界。不得给眼罩时长、交替训练频率、药物或“拖动到 100% 就治好”的交互。

四步外层路径仍为正常输入→机制变化（三段卡）→功能区别→练习；“正常输入”描述机制基准，不对用户或示例儿童下正常/患病诊断。双眼机制图可显示单眼输入优势差异的文字/线型，但不设置无法校准的“大脑权重 0—100”滑块。

### 5.5 首期练习

| ID | 正确结论 | 误选反馈重点 |
| --- | --- | --- |
| `amb-cause-01` | 两眼屈光状态差异、斜视、儿童期视觉输入受遮挡都可能与弱视形成有关 | 不把全部原因归为一条眼外肌或晶状体 |
| `amb-appearance-02` | 眼位看起来整齐不能单独排除弱视 | 用默认屈光参差案例返回对照 |
| `amb-input-03` | 光学输入改善不等于已形成的视觉发育问题瞬间消失 | 明确输入图与处理结果是不同层次 |
| `amb-distinction-04` | 斜视与弱视不同；可能关联，也可分别存在 | 返回两章的定义及对应示意，不用“弱眼/懒眼”作唯一解释 |

### 5.6 验收底线

默认案例眼位对准且不出现晶状体混浊；切到其他原因后场景可准确恢复；改善输入不瞬间恢复处理结果；三种原因均有独立解释；无年龄/遮盖处方。动画可暂停，语言切换、错题复习和返回结构均保留当前案例与已答状态。

## 6. 四章之间的关系与界限

| 容易混淆的概念 | 交互必须传达的关系 |
| --- | --- |
| 近视 vs 白内障 | 前者可用焦点与视网膜关系说明；后者本章强调晶状体混浊及散射，不能只改焦点 |
| 青光眼 vs 白内障 | 分别强调视神经损害、晶状体混浊；功能影响也不能用相同滤镜替代 |
| 斜视 vs 弱视 | 前者是双眼眼位不一致；后者与视觉发育及视功能有关，外观不能互相替代判断 |
| 儿童期白内障 vs 弱视 | 输入受限可影响视觉发育，但白内障与弱视不是同一结构病变 |
| 高眼压 vs 青光眼 | 风险因素/机制关联与疾病诊断不是一回事；保留正常眼压情景 |
| 软件重置 vs 治疗 | 重置只重开教学场景，不表达真实损害逆转或临床疗效 |

章节之间只通过“相关机制”链接，不把一个案例的变化状态继承为另一疾病的患者病史。无组合患病模式；用户以后明确要求时，再设计多机制共存及新的验证范围。
