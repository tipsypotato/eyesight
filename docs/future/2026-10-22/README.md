# eyesight 后续优化与功能拓展交接包

版本：1.1 · 归档日期：2026-10-22 · 状态：待实施规格及参考项目研究

## 交付目标

在现有成人右眼互动 demo 上，补齐“看懂结构 → 观察因果 → 联系常见眼病 → 检验理解”的教学链路。服务医学入门教学与大众科普；保持中文、英文等价可用。本文档包供另一个模型或工程师实施，本次归档没有修改应用代码，也没有把下述规划标为已完成。

架构方向：继续使用 React + TypeScript + Three.js + Zustand + Vite；复用现有几何、相机、剖切、归一化光学和双语内容。先改善现有工作区，再扩展单眼疾病，最后引入确有必要的双眼与视觉发育表达。

## 依据及证据边界

已经检查本地 eyesight 源码、既有验证记录及先前桌面/窄屏体验。后续开发沿用整体→局部→分层的观察方式、相机定位、结构命名与来源元数据；规划与脚手架不能视为已完成体验。

归档时对本地 eyesight 的判断包括：小眼底结构难定位、部分光学说明重复、比较依靠记忆、导览与测验衔接松散、误选反馈不足，以及窄屏操作参数时看不到模型。当前改进状态见上方实施进度，医学依据及具体引用见第四份文档。

## 分期与交付切片

| 阶段 | 必交范围 | 结束条件 |
| --- | --- | --- |
| A：基础体验 | 定位/标签、剖切预设、状态恢复、移动端操作区 | 小结构可定位，切面可预测，语言和切换模式不破坏任务 |
| B：因果与学习 | 光学实验、同条件对照、短导览任务、反馈与错题 | 参数有明确后果，导览能直接进入对应测验 |
| C：单眼疾病 | 白内障、青光眼 | 分别讲清晶状体混浊和视神经损害；不能由一个滑块推导临床病情 |
| D：双眼与斜视 | 左右眼实例、注视目标、内斜/外斜 | 正常会聚与偏斜可区分，左右/鼻颞关系正确 |
| E：弱视 | 视觉发育机制、三类原因案例、与斜视区分 | 光学输入、眼位与视觉发育结果可分别解释 |
| F：后续可选 | 视网膜微观层级、分享/教师展示、更多剖面 | 仅在明确安排相应任务时实施，不混入 A—E |

推荐顺序：A → B → C（白内障后青光眼）→ D → E。F 中场景分享可在 A 的状态结构稳定后单独安排；微观视网膜放在 B 之后。阶段不是工期承诺；每次只实现被分配的任务切片。

## 全局不变量

1. 成人右眼基线与当前外观细节必须保留；拓展为左眼或儿童发育机制时显式说明模型范围。
2. 眼球坐标中的鼻侧、颞侧、上、下、前、后不随镜头旋转改变。瞳孔是开口，眼房是空间；光线在视网膜结束，之后另画神经信号。
3. 光学数值是归一化教学参数，疾病控制量是示意参数；不输出验光处方、临床分期、患病概率或治疗剂量。
4. 语言切换只换文字，不重置镜头、切片、实验参数、导览步骤、答案、随机顺序或得分。
5. 同一时刻只有一个工作区拥有场景控制权。导览、测验和疾病不能争抢材质、相机或目标高亮。
6. 新增内容携带来源与审校状态。LLM 翻译校验不等于眼科专家审核，不得伪造“已审校”。
7. 继续按需渲染，维护 resize、动画取消、WebGL 恢复和资源释放；优先复用现有能力，不为本包默认增加后端、账户或外部模型资产。
