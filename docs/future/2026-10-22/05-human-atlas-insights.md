# 05 · human-atlas 对 eyesight 的启发

归档日期：2026-10-22 · 交接包增补版本：1.1 · 状态：源码研究与后续建议，未实施。

研究对象：[ashemag/human-atlas](https://github.com/ashemag/human-atlas)，固定提交 [1c38bf35c254a891200d3cedecfd57abebe83d8d](https://github.com/ashemag/human-atlas/tree/1c38bf35c254a891200d3cedecfd57abebe83d8d)，提交日期 2026-09-06。已阅读应用、场景、解剖类型、模型目录、排布、手势、下载、工具接口、归属和验证脚本。在线 demo 在本次内置浏览器中加载超时，未取得有效页面截图；本文是源码研究，不是在线体验审查，也没有验证其实际材质效果或真实设备表现。

## 1. 对当前路线的判断

eyesight 应继续使用目前可控的成人右眼模型、归一化光学和分阶段疾病教学。human-atlas 更有价值的借鉴是“把结构组织清楚、让它容易被找到和操作”，以及提供候选解剖资产。无需因此改技术栈、换成全身图谱或重新制作已完成的角膜/虹膜/晶状体/眼底。

推荐先补强：**概念与网格分离、避开面板的定位、多指手势防误选**。随后考虑结构图鉴与静态眼眶/眼外肌观察。四病顺序仍按白内障→青光眼→斜视→弱视，不以导入外部模型作为前置。

01—04 仍是基础实施规格；本篇指出增强落点和验收增量，接手者只在被安排的任务中采纳相应项。文中的图鉴、肌肉资产、工具接口和渲染批处理不自动加入 A—E 的必交范围。

## 3. 优先补强一：从单个结构到教学关系组合

### 3.1 建议场景

保留原结构列表与稳定 ID，在相关资料卡增加“关联观察”动作。组合显示“教学组合”，不冒充一个新器官，也不重复统计结构数量。

| 入口 | 关联成员 | 观察意图 |
| --- | --- | --- |
| 晶状体 → 观察调节关系 | ciliary-body、zonules、lens | 睫状体、悬韧带、晶状体如何共同参与调节 |
| 前房 → 观察房水路线 | ciliary-body、posterior-chamber、pupil、anterior-chamber；C 后加 trabecular-meshwork | 空间、开口、产生与流出区域相互区分 |
| 视网膜 → 观察眼底地标 | retina、macula、fovea、optic-disc | 包含关系及鼻颞位置，不把黄斑/中央凹当成可拆卸器官 |
| 青光眼机制 → 观察受累部位 | optic-disc、optic-nerve；配独立视野说明 | 结构损害与功能说明对应，仍遵守 02 的不可定量反推边界 |

### 3.2 自然交互顺序

1. 用户先选一个结构，资料卡给一个与当前问题匹配的关联观察入口。
2. 点击后保留 primary 选中结构；关联成员采用次级轮廓和图例，一次只打开一个教学组合。
3. 只临时显露必要成员并拟合组合的联合边界，资料卡显示每个成员及其角色。点成员可继续查看该成员，不丢组合上下文。
4. “返回单结构”恢复进入前的图层/隔离/相机；语言仍用最新值。进入另一个模式、测验或步骤时清除旧组合覆盖。
5. 测验未答时关闭关联名称、成员列表和组合高亮，避免提示答案。

实施落点：T02 的结构关系与 T07/T08 的教学调用。优先保留 `selectedId` 的原含义，把关联集作为当前工作区的派生观察状态；不为此重写全部选择接口。双眼阶段成员必须带 EyeRef，不能错误地同时高亮另一侧。

验收增量：组合有多个几何仍只有一个主要资料上下文；临时显露不永久改变原图层；重复切换不累计透明度；返回后恢复；各成员有明确眼侧与名称；正常学习和未答测验的名称暴露规则分别成立。

## 4. 优先补强二：定位要考虑真正可用的视口

现有方案已经要求小结构定位和移动底部面板。human-atlas 的具体启发是将两者做成同一条计算链，避免“相机确实靠近了，结构却躲到面板后”。

建议 T02/T04 共享当前可见区域信息：场景容器矩形减去标题、工具、安全区域以及实际覆盖模型的面板。预留量使用组件实际测量结果，而不是复制参考项目固定的 350 px 等数字。

定位目标的占比按这个可用矩形计算；资料面板从半屏到全屏、手机旋转或英文换行改变面板高度时重新计算。用户正在转动镜头时只调整必要的投影偏移，不重复触发飞入动画；需要重新拟合时等手势结束后执行一次。关闭面板/退出隔离时清除偏移，避免下一模式整体偏到一边。

接手者可复用现有 CameraRig，增加可用区域参数；是否使用 setViewOffset 由现有相机实现决定，不必照抄对照项目的 DOM 查询。相机位置、target、zoom 及投影偏移的恢复必须一致。

验收增量：390×844 半屏资料、844×390 横屏资料、320×568 紧凑屏和桌面详情展开下，中央凹/晶状体定位均落在未被遮挡区域；关闭面板不残留偏移。浏览器模拟视口检查不能替代真实手机触控验证。

## 5. 优先补强三：防误选与小目标可选性

本次读取的 eyesight `EyeEngine` 只记录按下坐标，并在抬起时检查两点距离是否超过 6 px；没有同等的完整多指/取消序列判定。由此可以识别需要补测的情况，尚未实机复现，不能把源码推断写成已观察到的 UI 故障。

建议在 T04 补一条独立手势判定：

- 鼠标沿用 6 CSS px、触摸暂用 12 CSS px 作为初始容差；之后根据真实设备结果调整。
- 记录 pointerId 和整个手势的最大位移；曾经拖远又回到原点仍是拖动。
- 任意时刻同时有两指，整段序列都不能触发点选；不是第二指抬起后立即恢复点击资格。
- pointercancel、失去指针捕获、离开工作区或切模式时清理；下一次正常点击可恢复。
- 已答/未答测验仍遵守原模式规则，不能因增加手势助手而重开禁止的场景选取。

小目标采用“可见目标的扩大命中范围”作为辅助，而非隔空命中隐藏组织。实际几何命中优先；近邻候选须经过可见性、遮挡、切面、眼侧过滤。两个候选接近时展示可选择的名称/定位入口，不随机选一个。现有标签本身可提供 44×44 CSS px 的交互热区。

验收增量：点击、拖动离开再返回、多指缩放依次抬起、取消、取消后新点击、面板拖动、模式切换后抬起都各有明确结果。参考项目的纯函数测试可以借鉴，不代表其真实多点触摸设备已经通过验证。

## 6. 可选拓展：结构图鉴与静态肌肉观察

### 6.1 结构图鉴

保留当前“分层展开”来讲空间关系；另提供明确命名的“结构图鉴”，用于比较形态和找结构。不要让一个没有说明的 0—100% 滑块同时承担解剖展开、平面排布和物理成像。

图鉴只在结构探索进入：保存原场景→暂停光路/房水/生理动画→按可见教学对象分组排布→选择卡片查看→“回到眼球原位”。排布随可用宽高变化，隐藏项不占格，视口不够时分组滚动/分页；不是把 17 个对象同时压成小点。

组织、区域、空间采用不同呈现：组织可显示独立形态；黄斑/中央凹显示带周围视网膜的局部片段；前房/后房显示边界与相邻结构。瞳孔仍是开口。图鉴位置不代表体内位置，原位才演示光传播和房水路线。不能让计算光线穿过已经移开的晶状体。

实施归入 F 的可选增强，不阻塞现有 T01—T15。若安排此项，再增加可见对象排布、无重叠、空列表、返回状态和区域/空间语义测试。

### 6.2 静态眼眶/眼外肌观察

human-atlas 的左右眼及六类眼外肌资产可以作为候选参考，让斜视从“两只悬空眼球”进一步连接到周围结构。首个 D 阶段仍只交双眼、注视目标和偏差，肌肉视图后置。

首期可选实现只做静态观察：进入后眼球回到中性位，显示选中的肌肉及眼侧/名称；“回到眼位实验”恢复保存的偏差和目标。不要直接把静态肌肉随眼球刚体旋转，也不要让旋转后的附着点与静态肌肉分离；动态肌肉变形与力学属于另一任务。不能用每条肌肉一个“松紧”滑块解释所有斜视。

## 7. 眼部资产核查：有价值，但不能直接整包替换

以下事实来自固定提交的 [atlas.json](https://github.com/ashemag/human-atlas/blob/1c38bf35c254a891200d3cedecfd57abebe83d8d/public/models/atlas.json)，本次已解析其 JSON，没有读取/渲染所有二进制几何。

### 7.2 不可误读的缺口

在本次 concepts 英文名称检索中，没有找到 pupil、posterior chamber、fovea、macula、optic disc/optic disk、trabecular、iridocorneal 的独立命名条目。结论仅限“当前目录没有提供这些独立可选概念”，不能推断相应表面一定没有开口或细节，也不能推及整个 BodyParts3D 数据库。

`right eyeball`（FMA12514）目前映射到 8 个几何，其中没有目录中单独存在的 FJ1367（右视网膜视部）、FJ1332（右前房）、FJ1338（右睫状冠）。所以按这个概念直接导出不能保证满足 eyesight 的完整结构清单。这是映射完整性问题的证据，不足以判定原始医学本体或实际几何错误。

引入时建立 eyesight 专用白名单：现有稳定结构 ID → 眼侧 → 外部概念/几何 ID 集 → 许可 → 坐标变换 → 已验证状态；验证成员存在之外，还要验证预期覆盖。不能把“所有引用的 ID 有效”当成“这个概念包含了所有应该包含的结构”。

### 7.3 推荐采用方式

1. 当前主模型继续保留。先用外部资产做独立对照/静态环境参考，验证后再决定是否替换某个局部。
2. 只提取明确需要的眼部子集，不让用户为眼部教学下载全部全身模型。目录的全部压缩几何合计 32,956,129 字节；眼部子包大小尚未测量。
3. 适配原始单位、眼球局部坐标、左右眼、法线、包围盒、接缝、可切面、命中及资源释放。包围盒须用实际使用的顶点/索引检查，不能只信名称和元数据。
4. 单独验证角膜连续性、瞳孔开口、晶状体/悬韧带关系、眼底地标、光线与视网膜重合；没有来源细节的黄斑/中央凹等继续保留现有示意，并标明来源混合。
5. 通过后再更新 THIRD_PARTY_NOTICES、内容来源和模型版本；仍需专业审校，不把外部真实解剖来源等同医学级精度认证。

应用源码为 MIT，模型归属另有要求。[官方 BodyParts3D 许可页](https://dbarchive.biosciencedbc.jp/en/bodyparts3d/lic.html)（2025-02-27 更新，本次读取）说明当前数据库为 CC BY 4.0；参考仓库 [ATTRIBUTION.md](https://github.com/ashemag/human-atlas/blob/1c38bf35c254a891200d3cedecfd57abebe83d8d/public/ATTRIBUTION.md) 登记了来源、简化和量化处理。若采用资产，保留归属并记录自己的修改；本次没有向 eyesight 复制模型或第三方代码。

## 8. 工程上借鉴什么、暂时跳过什么

值得借鉴：可见集合驱动排布；概念成员去重；下载数据长度/解码校验；手势纯函数；布局与查找/检查契约的确定性测试。眼部子集如未来采用分块包，再安排压缩、失效和失败恢复，不为当前程序模型预建下载系统。

暂不照搬：成千上万部件的合批/GPU 状态纹理、全量组件依赖、全身模型和新框架。其代码在 dirty 时才 render，但 requestAnimationFrame 循环仍持续运行；不能将其等同于完全停止空闲帧。当前 eyesight 已有按需调度和 WebGL 恢复，不能为了参考另一项目而退回持续空闲循环或仅提示重载。

可选 WebMCP 只暴露 find_anatomy 和 inspect_anatomical_structure，支持时注册、不支持时仍可使用 UI。启发是未来教师助手可调用有限的“搜索/定位/切步骤”命令，复用可见操作；它不等于已实现 AI 问诊、自动教学或翻译审校。本包仍不要求运行时 LLM、后端或账户；自动化入口应遵守未答测验的保密规则，不能绕过状态检查。

## 9. 建议优先级与现有任务落点

| 优先级 | 增补 | 落点与完成判据 |
| --- | --- | --- |
| 优先 | 面板感知的定位、完整手势序列 | T02/T04；小结构在剩余视口可见，拖动/多指/取消不误选 |
