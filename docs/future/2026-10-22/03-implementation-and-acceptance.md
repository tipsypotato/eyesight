## 3. 数据与接口约束

下面是目标契约片段，供兼容实现使用，不是可直接整段替换现有源码的补丁。

### 3.1 单眼兼容、眼侧与结构

```ts
type EyeSide = 'right' | 'left';
type EyeRef = { side: EyeSide; structureId: StructureId };
type DiseaseId = 'cataract' | 'glaucoma' | 'strabismus' | 'amblyopia';
type KeepSide = 'negative' | 'positive';
// StructureId 保留原 17 项；T10 再追加房角、小梁网两项。
// 旧 SceneState.selectedId 在右眼工作区继续有效，通过适配映射为 EyeRef。
```

不得为了双眼支持一次修改所有调用方为新的不兼容签名。先让单眼路径默认 right，再让双眼场景和选择携带 side；标签 DOM key、材质缓存、命中反查均用 side + structureId。两眼不能共享会被一侧改色/透明度修改的材质实例。

坐标遵守 02 的患者坐标；当前单右眼局部 +X 鼻侧、+Y 上、+Z 前继续成立。左眼的眼底位置和表面朝向显式校验；资源缓存可共用不可变数据，但单眼参数和可变资源需要隔离。

### 3.2 状态所有权与快照

```ts
type SceneSnapshot = {
  selected: EyeRef | null;
  layers: Record<StructureId, LayerMode>;
  isolate: EyeRef | null;
  clip: { enabled: boolean; axis: ClipAxis; offset: number; keepSide: KeepSide };
  explode: number;
  labels: boolean;
  camera: {
    position: [number, number, number];
    target: [number, number, number];
    zoom: number;
  };
  presetId: string | null;
};
```

快照只表达场景，不包含 lang、答题记录、来源审校状态或运行中的 Three.js 对象；光学/疾病参数由所属模式草稿持有。双眼场景可在该类型旁提供按 eyeSide 的图层映射，不要求把所有单眼 UI 改成双眼图层编辑器。

切换顺序固定：捕获当前有效状态 → 取消动画/拖动 → 恢复临时几何和材质 → 释放离开场景的专属资源 → 应用目标模式草稿/默认值 → 单次失效触发重绘。可用递增 transitionToken 防止旧回调覆盖新状态；不要引入第二套全局事件总线。

`resetCamera`、`resetScene`、`restartLesson`、`restartQuiz` 是不同意图，不能继续共用会清空全部学习信息的 reset。重开课程清除该轮操作达成状态，不删除历史成绩；清除本地学习记录才删除持久化学习内容。

### 3.3 光学追迹

保留 `computeOptics(preset)` 的三基准输入和现有 OpticsResult 输出，原调用不改义。增加通用 `traceOptics(input)`；旧函数改为调用同一个追迹核心与基准参数，禁止保留两套不同公式。输入至少覆盖眼轴、物距档位、调节、瞳孔、外部镜片开关；输入处校验枚举、有限数和范围。

通用结果提供现有 rays/几何位置，以及 `focusZ: number|null`、`focusKind: 'real'|'virtual'|'parallel'`、有效入瞳光线数量、视网膜交点与离散程度。旧三基准均为有限实焦点，因此兼容输出中的 focusZ 仍为 number；通用平行/虚焦结果走新类型，不能给旧类型偷偷塞 NaN。

计算约定：传播方向从前向后，使用 s=zStart-z，斜率 m=dh/ds。自由传播 d 时 h'=h+m·d；通过薄透镜时 m'=m-P·h。有限轴上物点产生的光线应从同一个物点出发；平行入射则 m=0。依次经过外镜片（启用时）、角膜等效面、瞳孔孔径、晶状体等效面和视网膜。到达瞳孔之外的光线被截断，不穿过虹膜实体。

保持当前基准：corneaZ=1.05、lensZ=0.5、glassesZ=1.7、正常 retinaZ=-1、轴性近视=-1.22；角膜等效屈光参数沿用 0.35。放松晶状体参数沿用当前正常焦点校准。调节增量上限通过正常眼轴、物点 z=2.5 的例子求解，使其可聚焦到视网膜；无外镜片时不改变角膜参数。为轴性近视求解发散镜片仍使用同一追迹的视网膜交点条件，不能把数值输出为临床屈光度。

焦点位于视网膜之前时分段画交点；之后的几何延长属于辅助虚线。模型内部实线仍以视网膜为终点。定性离焦指标来自入瞳有效光线在视网膜处的交点离散；无有效样本时显示未得到样本，不能除以零。瞳孔孔径、三维孔洞和二维示意需同源。

### 3.4 疾病状态

```ts
type AmblyopiaCase = 'anisometropia'|'strabismic'|'deprivation';
type AmblyopiaCaseDraft = { mechanismStep: 0|1|2; inputImproved: boolean };
type DiseaseDraft =
  | { id: 'cataract'; step: 0|1|2|3; opacity: number;
      view: 'context'|'lens-detail'; preview: 'test-chart'|'glare-scene' }
  | { id: 'glaucoma'; step: 0|1|2|3;
      scenario: 'normal'|'outflow-risk'|'established-damage'|'normal-tension';
      view: 'outflow'|'nerve'; outflowRelieved: boolean }
  | { id: 'strabismus'; step: 0|1|2|3;
      alignment: 'normal'|'esotropia'|'exotropia'|'custom';
      deviationDeg: number; affectedEye: EyeSide; targetDistance: 'far'|'near';
      visualExplanation: 'alignment-only'|'adult-diplopia'|'child-suppression' }
  | { id: 'amblyopia'; step: 0|1|2|3;
      causeCase: AmblyopiaCase;
      caseDrafts: Record<AmblyopiaCase, AmblyopiaCaseDraft> };
```

每章有自己的 draft，不能用一个“severity”字段代替所有病因。青光眼既有损害由 scenario 选择，不是 outflowRelieved 的反函数。弱视的 inputImproved 只改变输入表现，不清除已形成的视觉发育问题。处于正常结构步骤时使用基准渲染派生值，不覆盖 draft 中保存的病变参数。对照开关、播放状态等工作区瞬时 UI 状态无需写入医学数据。

### 3.5 题库、进度与审校

题目最少字段：稳定 id、kind、双语题干、可选 EyeRef 目标、稳定 option.id、双语选项、correctOptionId、每选项的双语解释、来源 ID、审校状态。题目 ID 不可用结构 ID 替代；两个题目可以指向同一结构。

答题状态在每个会话内 keyed by questionId，保存 sessionId、题集 context、题序、选项序、selectedOptionId、revealed、提交时间和题库 contentVersion。context 区分基础识别、各课程和各疾病；活动会话指针与已完成结果分开，不用单个全局 answers 覆盖不同练习。显示文案从当前语言解析；不保存某种语言的渲染后反馈。沿用现有“一次提交/揭晓不计分”的纯函数约束。静态教学 app 不提供考试防作弊保证，但未答时不得从正常界面、ARIA 或 URL 提前暴露目标和正确项。

持久化 schema 校验失败按字段/模块降级，避免一次坏 JSON 导致整个页面空白。内容版本更改时，保留可识别历史结果；失效题目不进入新错题队列。以实际结构 ID 验证覆盖，不把当前数量 17 永久硬编码为测试结论。

## 5. 必须先出现的失败用例

以下是实施时的红→绿约束；先确认新用例能暴露未实现/错误逻辑，再修复。不要通过删旧测试、放宽断言、调高构建警告阈值或屏蔽控制台错误制造通过。

| 场景 | 检查内容 |
| --- | --- |
| 切模式清空学习/相机 | 在 tour 末步、quiz 已答时分别离开/返回；步骤、题序、选项序和已答状态仍在 |
| 相机旋转让切面翻侧 | 固定平面/offset/keepSide，绕一圈；同一已知测试点的裁切与命中结果不变 |
| 近视/病变残留 | normal→myopia→疾病→explore，位置/材料应与正常快照一致，且资源不会不断增加 |
| 左眼方向错误 | 同一内斜语义施加到两眼，均朝各自鼻侧；黄斑相对视盘在各自颞侧 |
| 眼压与损伤强行绑定 | established-damage 下改善流出；损害结果保持；normal-tension 仍可显示损害 |

| 本地状态失效 | 存储拒绝、坏 JSON、旧内容版本、未知 ID；仍能打开和继续默认学习 |

## 6. 验收场景

执行者记录实际环境、命令/操作、结果及证据位置。以下均是待验收标准，本次归档未执行功能测试。

### AC-01 · 模式、语言与状态

给定导览第 4 步或测验第 2 题已答，切到探索、旋转镜头，再返回；步骤/答案保持，两个模式各自镜头恢复。切到英文后重复，文字切换且题序、选项序、得分不变。连续快速选择三个目标，最终镜头/资料只对应最后一个目标，没有旧动画回写。

### AC-02 · 重置、撤销与恢复

修改剖切、展开、图层后重置视角，只有相机变化；再重置场景，学习记录不变。连续拖动一个滑块后一次撤销恢复拖动前值；20 条上限和跨步骤清栈符合规则。刷新恢复学习位置与对应默认场景，不恢复过期动画。存储禁用/损坏时页面仍可操作并只提示一次。

### AC-03 · 小结构定位

完整眼球中从列表选择中央凹，出现眼底预设和黄斑/视盘参照；定位后目标可辨认且不穿模。返回定位前视角能恢复。画布普通点击只选中；重复点击不自动跳镜头。隐藏/被裁几何不能抢占命中，显露操作有可撤销提示。

### AC-04 · 标签、搜索与方位

旋转一周，鼻/颞/前/后语义不变。完整眼球不透出内部普通标签；被选中遮挡目标给定位提示；标签不压住主要操作。中英/拉丁名与白眼球可搜到结构，黑眼珠给虹膜/瞳孔两个解释；清除搜索保留选择。quiz 未答时普通界面和 ARIA 不出现目标名或正确标志。

### AC-05 · 剖切、展开与命中

逐一选择六预设，从任意旧隐藏状态都得到同一结果；目标不在预设显示集时选择清空。三个平面在 offset=-1、0、1 和两种 keepSide 均无异常；镜头改变不翻保留侧。展开+剖切+隔离组合后还原，材质/颜色/位置与初始一致；封闭眼球内部不穿透，展开时不误套封闭遮光。

### AC-06 · 窄屏与无障碍

在 390×844 和 1440×900 CSS px 视口检查；窄屏 `scrollWidth === clientWidth`，半屏面板内操作光学参数时模型同时可见；长错误反馈下“下一题”始终可达。英文长名称不截断关键动作。键盘可切导航/面板、操作滑块、退出临时层；减少动态效果时无自动长过渡且信息完整。触点、焦点、对比度达到 01 的数值。真实设备/读屏未测时单独列出，不以模拟视口结果代替。

### AC-07 · 光学一致性

自动检查 normal 焦点在 retinaZ=-1，myopia 焦点在视网膜前，corrected 发散镜片参数为负并在 retinaZ=-1.22 聚焦；三者与既有校准相容。有限物点的所有入射光回溯至同一物点；调节能在正常眼轴近物例子重新聚焦；瞳孔变小不改变透镜参数；孔外光线被截断。二维与三维使用同一结果，实线终止视网膜，平行/虚焦/无样本均无 NaN/Infinity 渲染。退出后几何拉伸恢复。

### AC-08 · 对照与生理

保存正常对照后只改眼轴，两视图只有声明变量不同，镜头同步；手机切换同一位置。正常对照不随当前变化。播放看近时肌肉、悬韧带和晶状体趋势相符；光线不进入视神经，神经信号有不同图例。暂停/切模式/减少动态效果均终止自动动画而保留解释。

### AC-09 · 学习闭环

三课 11 项操作任务逐一检查，默认场景不自动视为达成。从一课末步点击“练习本课”，直接进入对应 3 题；首批 9 道题与 01 的 ID/结论一致。误选反馈解释选择为何不符，并可返回结构后继续原题。跳过操作标记已访问；已看答案不记答对；完成结果分类正确。只复习错题时仅含答错/已看答案，语言切换不改变顺序。

### AC-10 · 题库与持久化

两个题目指向同一结构仍分别计分；重复点击只提交一次，揭晓不加分。切换题集不覆盖另一题集未完成会话；刷新恢复 sessionId/选项序/已答状态；旧内容版本不把已删题当成新题。重开一轮生成新会话，历史保留。所有新题干/选项/反馈有双语和来源；未过翻译校验的内容不得声称已审核。

### AC-11 · 疾病工作区

首次进入为白内障正常步骤；变化参数在回看正常时被保留；换章/返回后恢复各章进度。退出疾病恢复来源工作区；无材质/眼轴/动画残留。章内练习调用同一答题规则，正常/变化对照不清除参数或成绩。

### AC-12 · 白内障

opacity 从 0→0.55→1 仅改变晶状体混浊示意与对应定性预览；角膜、虹膜、眼轴和光学聚焦校准不变。瞳孔仍是开口，正常侧清澈。测试图/眩光场景同条件比较，三题与误选反馈完整，离开章节外观可还原。

### AC-13 · 青光眼

两新增目标种类和位置正确；静态/动画路线均是睫状突→后房→瞳孔→前房→小梁网。四情景可独立选择：风险不自动有损害，正常眼压情景可有损害；改善流出不清除已有损害。视野图是标注的定性示意，非整圈必然黑边；无诊断阈值或压力到损伤的连续公式。四题覆盖 02 定义的误区。

### AC-14 · 双眼与斜视

normal 下近/远两眼方向都指向共同目标；右内斜、左内斜均向各自鼻侧，外斜相反。左眼黄斑/中央凹位于视盘颞侧，法线/选取正常。一眼高亮/混浊不改变另一眼材质。3D 旋转后眼侧、鼻颞和偏差含义保持。三情境说明不把复视/抑制设为必然，三题可完成。切回单右眼后无双眼资源和相机残留。

### AC-15 · 弱视

默认屈光参差例眼位正常；三原因独立恢复、三机制卡可回看。改善输入只改相应光学/眼位/遮挡输入，不自动清空视觉发育问题。标题说明儿童发育机制与成人网格范围，文字包含可影响双眼的边界，无年龄阈值/训练处方。四题及斜视关系入口保持原进度。

### AC-16 · 微观扩展（仅 T14）

从指定宏观位置进入局部层级后可精确返回；普通视网膜光方向与神经信号方向区分，感光细胞/双极/神经节顺序正确；中央凹特化没有被普通剖面取代。缩放与语言不丢上下文。

### AC-17 · 分享与教师展示（仅 T15）

支持场景编码往返；非法枚举/非有限数/未知结构/超长 hash 安全降级。链接包含所声明场景但不含答案、成绩或个人记录。新浏览器打开恢复相同公共场景，无过期动画；PNG 的来源/范围信息可读，展示模式有返回入口。无任意 HTML/远程脚本执行路径。

### AC-18 · 通用发布门槛

新增内容的双语键、来源、LLM 校验记录完整；无新增运行时翻译依赖。运行相关单元测试与全量 build，记录实际数量和构建警告。模式反复进入/退出不持续增加材质、纹理、监听器、RAF；页面静置停止无用渲染；WebGL 丢失/恢复后可重新呈现。现有角膜、虹膜、晶状体及眼底回归保持。

## 8. 风险与回退

| 风险 | 处理与回退方式 |
| --- | --- |
| 新版基线与接手源码不一致 | 保留用户修改，重新读实际调用链；指纹用于识别差异，不用于强制覆盖 |
